# TinyPretrain 教学模型卡

这是训练代码的说明，不是已经训练好的生产模型发布。实际运行权重位于各自输出目录，须随实际配置与验证记录单独交付。

- 用途：学习文本编码、因果预测、反向、优化、评估和检查点恢复。
- 架构：默认 2 层 Pre-LayerNorm Transformer，隐藏维度 128，4 头，4 倍 GELU 前馈，位置表 64，输入输出共享权重；参数量以程序实际统计为准。
- 编码：UTF-8 单字节 ID 0–255，EOS=256，无 padding；生成解码使用替换模式，可能有乱码。
- 语料：本项目原创短句与模板。200 个训练文档、40 个验证文档，主题重叠；先划分文档后构建窗口。
- 目标：下一字节 token 预测，允许跨 EOS 注意力，训练有放回抽样窗口；固定长度所有位置计入损失。
- 优化：FP32 AdamW，统一权重衰减，线性预热及余弦衰减，梯度范数裁剪。
- 验证：全局固定种子窗口列表，按 rank 间隔分配并汇总 NLL 与 token；默认全局 16 个窗口，不随 DP 数变化。窗口可重叠，不代表真实世界泛化或任务能力。
- 实测证据：`results/cpu-reference.json` 绑定默认 CPU 100 步的配置、数据与训练代码身份，含原始 loss/PPL、固定索引和生成片段；单种子短跑不支持能力或性能外推。
- 分布式：已在本机 Windows/PyTorch 2.11 CPU 上运行两进程 Gloo 固定样本单步梯度、更新和验证 loss 对照。完整多步 DDP 训练/恢复、CUDA/NCCL、多机与生产吞吐未验收，见根目录 VALIDATION.md。
- 局限：极小规模、短上下文、人工模板语料；不适合生产推理，不适合事实问答或能力宣传。
- 恢复：仅可信格式版本 2 检查点；要求相同规范化 train.py 哈希、PyTorch 版本、world size、数据与核心计划。源码身份缺失或改变即拒绝，不保证跨硬件逐位一致；Git HEAD 作为来源记录。
- 新阶段：`--init-weights` 仅继承架构/编码匹配的权重，重建优化器、计划、计数与随机状态，记录来源哈希；不做词表或上下文迁移。同语料演示不代表领域适应收益。
