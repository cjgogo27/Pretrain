## 先弄清承诺的边界

预训练项目常把“基础模型训练完成”“可以聊天”“评测提高”和“可稳定部署”混在一起。建议按下面顺序摘读，每节可以先读到“一句话听懂”，再检查本节的产品/PR 问题。

| 阅读 | 主要收获 | 对外沟通前要核对 |
| --- | --- | --- |
| 1.1 预训练是什么 | 预训练、续训、后训练的不同 | 模型究竟完成了哪个阶段 |
| 1.3 系统架构 | 数据、模型和基础设施怎样分工 | 项目目前贯通了哪些接口 |
| 2.1 数据来源 | 配比、质量与唯一数据量 | token 是否包含重复消费 |
| 3.5 预算 | 假设、有效速度与生命周期 | 时间数字是否来自实测 |
| 5.2 能力评测 | 分数属于特定条件 | 模型、题集、提示与评分是否一致 |
| 5.3 可信比较 | 污染与选择偏差 | 是否只报最好一次 |
| 6.5 模型交付 | 权重之外的交付包 | 有无配置、分词器、报告和模型卡 |

## 用三个问题检查一段宣传

1. 这是已运行并验证的结果，还是计划与预算估算？
2. 对比基线、数据和评测条件是否写清楚？
3. 结果覆盖了哪些任务，哪些能力还没有证据？

例如“1B 参数、20B token、41.7 小时”在本教程里是带假设的预算算例，不是我们已经训练出的模型。“最小实验能跑”也是流程验证，不是生产大模型能力证明。

遇到具体技术词，可以先查 [术语表](/Pretrain/07-appendix/a-glossary/)，再回对应章节看上下游影响。遇到硬件性能或规模数据，应沿参考来源核对测试条件。
