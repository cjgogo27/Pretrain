## 现场问题

你算出一个 1B 模型的 BF16 权重只占约 2 GB，于是准备在一张小显存卡上完整训练。启动后，显存却远超这个数字。

> 权重之外，训练还保存了什么？

<SectionQA id="3.4" mode="ask" />

## 参数量只回答一个问题

**参数量（Parameter Count）**是可学习数值的总数。词表嵌入约为 $Vd$；标准多头注意力投影约为 $4d^2$；采用 4 倍扩展的两层前馈约为 $8d^2$。忽略偏置和归一化时，每个标准 block 约 $12d^2$。门控前馈、GQA、共享权重等会改变结果，最终应以实际模型枚举为准。

计算共享权重时要避免重复计数。TinyPretrain 将 LM Head 与 token embedding 绑定，参数统计使用模型实际参数迭代，避免把同一矩阵算两次。

## 共享权重省掉哪里，算术还在哪里

默认词表 257、隐藏维度 128，一个词表矩阵有 `257×128=32,896` 个参数。若输入嵌入和无偏置 LM Head 独立，就需要两份；共享后保留一份，减少 32,896 个独立参数及其梯度、优化器状态。以 FP32 权重单独计，少存 131,584 字节。

输入仍要查表，输出仍要将 `[B,S,128]` 投影成 `[B,S,257]`，交叉熵仍要处理词表得分。两条用途的梯度共同累加到同一参数，不能把“少一份矩阵”说成“输出层没有计算”。实际 unique parameter 计数由 `model.parameters()` 去重，默认值 437,888。

## 训练显存由几部分组成

| 内容 | 为什么存在 | 是否随序列长度增长 |
| --- | --- | --- |
| 权重 | 前向使用的模型参数 | 通常不直接随长度增长 |
| 梯度 | 反向得到的参数导数 | 通常不直接随长度增长 |
| 优化器状态 | Adam 的一、二阶矩等 | 主要随参数量增长 |
| 主权重副本 | 某些混合精度实现保留 FP32 更新副本 | 依实现决定 |
| 激活 | 反向需要的中间结果 | 随批次和长度增长 |
| 临时缓冲与碎片 | 内核、通信和分配器需要 | 依实现与负载变化 |

常见混合精度 AdamW 的一种粗略参数状态预算是每参数 16 字节：2 字节权重、2 字节梯度、4 字节主权重和 8 字节一二阶矩。它是某类实现的估算，不是所有 BF16 训练的固定法则；例如原生 autocast 可能一直保存 FP32 参数，梯度和状态布局也不同。

> **一句话听懂**：权重大小说明存下模型要多少空间，训练峰值还要加上更新它、回传它和执行内核的空间。

## 计算量怎样估

对常见稠密自回归 Transformer，可以用 $C\approx6ND$ 近似估计训练 FLOPs：$N$ 是参数量，$D$ 是消费的训练 token 数。它把前向与反向的主要矩阵计算合并，忽略了一些注意力长度项、嵌入等实现细节，也不包含数据处理与评估开销。

教学算例：$N=10^9$、$D=20\times10^9$ 时，$C\approx1.2\times10^{20}$ FLOPs。长上下文、MoE、重计算和不同架构需要更细预算。FLOPs 是运算次数，FLOP/s 是每秒运算能力，二者相差一个时间维度。

## 从估算走到实测

先写状态预算，再在目标配置上跑短测试，记录峰值 allocated / reserved 显存、批次、长度和内核。激活重计算用额外计算换保存空间，状态分片则减少单卡常驻状态；它们解决的部分不同。不要把“理论能放下”当作“有足够运行余量”。
