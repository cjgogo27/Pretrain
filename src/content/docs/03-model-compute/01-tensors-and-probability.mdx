## 现场问题

调试信息里出现 `[8, 1024, 32000]`，损失是 3.2。你知道这两个数字都和模型有关，却无法判断内存为什么突然增加。

> 形状的三个维度各指什么？一个 loss 又汇总了多少次预测？

<SectionQA id="3.1" mode="ask" />

## 形状先于公式

**张量（Tensor）**是带形状和数据类型的多维数组。语言模型常用 $B$ 表示批次，$S$ 表示序列长度，$d$ 表示隐藏维度，$V$ 表示词表大小。整数 ID 的形状是 $[B,S]$，隐藏表示是 $[B,S,d]$，词表得分是 $[B,S,V]$。

某个张量占用的原始空间约为“元素数 × 每元素字节数”。例如 $8\times1024\times32000$ 个 BF16 得分约占 524 MB，即约 500 MiB。这只是一份 logits 的空间，实际峰值还包括中间激活、梯度和其他缓冲。

| 对象 | 形状示意 | 数据类型常见选择 | 含义 |
| --- | --- | --- | --- |
| input_ids | $[B,S]$ | 整数 | 每个位置的词表索引 |
| hidden_states | $[B,S,d]$ | 浮点 | 每个位置的上下文表示 |
| logits | $[B,S,V]$ | 浮点 | 每个位置对词表的得分 |
| labels | $[B,S]$ | 整数 | 正确的下一 token ID |
| loss | 标量 | 常在 FP32 汇总 | 有效位置的误差汇总 |

## 从得分到概率

对某一位置的词表得分 $z$，softmax 给出 $p_j=\exp(z_j)/\sum_k\exp(z_k)$。实现中通常使用减最大值等稳定技巧，而不是直接对很大的得分求指数。交叉熵函数一般接收 logits，自行完成稳定的 log-softmax；先做 softmax 再把概率当 logits 输入，会改变计算。

目标 token 为 $y$ 时，单个位置的负对数似然为 $\ell=-\log p_y$。模型给正确答案的概率越小，惩罚越大。若所有有效位置采用相同权重，训练损失就是这些位置的平均值。

> **一句话听懂**：张量形状说明模型在同时处理多少问题；交叉熵衡量模型给正确下一个 token 分配了多少概率。

## 用一个小数字检查直觉

若正确 token 的概率是 0.5，自然对数损失约为 0.693；概率是 0.1，损失约为 2.303。实际 loss 是许多位置的平均，不能倒推出每个 token 都有相同预测概率。

在 257 项词表上，完全均匀预测的交叉熵是 $\ln257\approx5.549$。这是字节教学模型的参考尺度，不是任意分词器或语料的通用基线。已有模型的初始输出也不必完全均匀。

## 为什么这些数会影响工程

增大批次、上下文或词表都会扩大某些张量；它们影响显存的路径并不相同。排查 OOM 时先写出峰值附近的实际形状，再看数据类型、激活保存和内核实现。只说“参数没变，所以显存不该变”会漏掉 logits 和激活的增长。
