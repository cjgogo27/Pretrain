## 现场问题

把一大批数据拆成 8 个微批次后，显存够用了，但训练轨迹明显改变。你发现程序在每个微批次后都更新了一次学习率。

> 微批次、优化器步和训练 token 为什么必须分别计数？

<SectionQA id="4.1" mode="ask" />

## 反向传播交付梯度

**梯度（Gradient）**描述损失相对于参数的局部变化率。反向传播利用链式法则计算这些导数；优化器再根据梯度与历史状态决定参数怎么变。调用 `backward()` 通常是向已有梯度累加，不等于自动更新参数。

**微批次（Micro-batch）**是一次前向与反向处理的数据。**梯度累积（Gradient Accumulation）**将多个微批次梯度积累后，才执行一次优化器更新。这样能在较小显存下获得更大的有效批量，但不减少所有计算成本。

## 三个计数器

| 计数 | 什么时候增加 | 用来回答什么 |
| --- | --- | --- |
| micro-step | 每次前向 / 反向 | 做了多少次微批次计算 |
| optimizer-step | 每次真正参数更新 | 学习率与优化器走到哪里 |
| trained-tokens | 消费有效训练 token 后 | 用掉多少数据与计算预算 |

固定长度、每个数据并行副本微批量为 $b$、长度 $S$、累积次数 $A$、副本数 $P$ 时，每次更新消费 $bSAP$ 个 token。$P$ 应是数据并行副本数，不是任意并行布局中的总 GPU 数。

例如 $b=2,S=1024,A=8,P=4$，每次更新消费 65,536 个 token。若改了累积次数但仍按旧步数衰减学习率，训练相同 token 时的学习率位置就会不同。

## 手算：100 与 900 个有效 token

A 微批次有效数 100，平均 loss=2，所以 token loss 总和为 200；B 有效数 900，平均 loss=4，总和为 3,600。正确总体平均是：

$$L=\frac{100\times2+900\times4}{100+900}=3.8.$$

直接平均两个均值只得到 `(2+4)/2=3`。这个错误不仅改日志：若也按它反向，得到 $0.5\nabla L_A+0.5\nabla L_B$，而正确梯度是 $0.1\nabla L_A+0.9\nabla L_B$。A 的每个 token 因而得到相对 B **9 倍**的权重。Loss 数值本身不告诉我们梯度方向；这里比较的是权重系数。

**归约为均值的两 rank DDP 假设**：rank 0 只有 A，rank 1 只有 B；模型初始参数相同，无自定义通信 hook，未使用 uneven-input join，全部 rank 同步一次，global 有效数 1,000 已知且不参与求导。每 rank 的反向标量应为：

| rank | 本地 loss 总和 Sᵣ | backward 使用的标量（P=2） |
| --- | --- | --- |
| 0 | 200 | `P×S₀/1000 = 0.4`，等于 `0.2×mean_A` |
| 1 | 3,600 | `P×S₁/1000 = 7.2`，等于 `1.8×mean_B` |

DDP 平均后是 $[\nabla(0.2L_A)+\nabla(1.8L_B)]/2=0.1\nabla L_A+0.9\nabla L_B$，恰好等于正确全局均值的梯度。0.4 / 7.2 是当前标量值，求导对象仍是对应的损失函数。**这两个 backward 标量不是各 rank 的报告 loss**；报告仍用全局 loss 总和 / 全局有效数。多个微批次时，分母覆盖本次更新所有 rank、所有微批次，且不能再重复除以累积次数。

固定无 padding、各微批次数量相同的默认实现则可用 `mean_loss/A`，因为每份材料有效数相等。不要把这条简式移植到变长批次。归约依据见 [PyTorch 2.11 DDP 关于 summed loss 的说明](https://docs.pytorch.org/docs/2.11/generated/torch.nn.parallel.DistributedDataParallel.html)。数值对照见 [6.3](/Pretrain/06-tools-practice/03-single-to-multi-gpu/)。

## 缩放与清零放在哪里

当各微批次有效 token 数相同，常见顺序是：清零梯度；重复 $A$ 次前向，对 `loss/A` 反向；完成同步；裁剪梯度；更新参数；前进调度器。若每批有效 token 不同，应按有效 token 总数加权，而非机械除以 $A$。

> **一句话听懂**：累积是在同一次更新之前攒梯度；参数更新和学习率前进应与“更新步”对齐。

## 分布式里还多一个约定

DDP 默认在反向过程中同步梯度。累积时可在前 $A-1$ 个微批次的前向和反向外包住 `no_sync()`，在最后一次触发同步。所有 rank 必须执行相同的通信顺序。在普通 DDP 的完整副本上，归约后每个副本持有相同完整梯度，可各自按同一阈值裁剪。分片场景不能照搬，见 4.3。

还应处理最后不足 $A$ 个微批次的情况：明确丢弃、单独缩放，或保持固定步数。不要悄悄用满批分母归一化一个不足量的更新。本书教学代码以固定步数和固定累积量组织循环，因此没有这个尾批分支。
