## 现场问题

你在周五更新了清洗脚本，却沿用同一个 `train.bin` 文件名。周一发现评估下降，团队已经无法确认训练到底读了哪一版。

> 怎么给数据一个可以追溯、可以拒收的身份？

<SectionQA id="2.5" mode="ask" />

## 数据版本要覆盖完整变换链

**数据清单（Data Manifest）**是连接原始来源、处理过程和训练输入的索引。它应该说明原始快照、清洗规则、去重版本、划分方式、分词器哈希、分片列表及校验值。相同文件名不是相同数据，大小相同也不是。

把 manifest 作为训练配置的一部分保存。若改变了分词器，旧 token 文件通常不再有效；若改变了验证划分，前后 loss 不能直接当成同一指标曲线。

## 三层验收

| 层级 | 检查内容 | 失败时怎么处理 |
| --- | --- | --- |
| 结构检查 | ID 范围、编码、分片校验、空文档、长度分布 | 拒绝损坏分片，重跑对应步骤 |
| 内容抽查 | 可读性、模板残留、领域覆盖、敏感字段处理 | 按来源和语言定位规则问题 |
| 训练探针 | 小模型损失、加载速度、样本回放、验证独立性 | 停止放大，固定条件查因 |

“通过”需要事先约定标准。例如不得有超出词表范围的 ID；划分间精确重复数应在既定规则下为零；各来源 token 量应与清单一致。质量抽查则要报告样本数、分层方式与发现，不要将有限抽样写成全量保证。

## 用一份最小清单把关系写清

```json
{
  "dataset_version": "example-v1",
  "tokenizer_sha256": "实际分词器文件的哈希",
  "split_policy": "document-group-before-tokenization",
  "normalization_version": "clean-v1",
  "train_tokens_unique": 1000000,
  "sampling": "with-replacement",
  "shards": [{"path": "train-000.bin", "sha256": "实际校验值"}]
}
```

这只是字段示意，数字不是本项目的实测数据。实际清单需要从处理结果生成，不能手工填一个看起来合理的值。分片校验只能证明文件一致，不能证明内容正确；内容规则还需要单独验证。

> **一句话听懂**：数据验收把“感觉能用”变成“哪一版、检查了什么、什么条件下可以开始训练”。

## 贯穿案例的落点

本项目的数据准备脚本生成 `train.txt`、`val.txt` 与 `manifest.json`，记录两份文件的 SHA-256 和文档数量。训练脚本将数据哈希写入检查点，恢复时核对当前文件。修改任意一个字符后再恢复，会被拒绝，避免悄悄改变运行的数据。

完成这一步后，数据流有了可追溯身份。下一章进入模型与计算，用张量、概率和预算解释这批数据怎样改变权重。
