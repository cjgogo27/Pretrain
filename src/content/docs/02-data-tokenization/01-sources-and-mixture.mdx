## 现场问题

你有网页、技术文档和代码三类数据。网页最多，于是按文件大小直接混在一起；训练后，技术术语的表现却没有明显改善。

> 文件最多的来源，应该占最多训练份额吗？

## 数据集不是一个文件夹

**数据混合（Data Mixture）**描述训练时从不同来源、语言和领域抽样的分布。原始字节数、文档数与 token 数不是同一单位。中文、英文、代码经过同一分词器后，每字节对应的 token 数可能不同；配比需要明确以什么为分母。

先写数据清单，再讨论比例。来源清单至少包含获取方式、可使用范围、语言、领域、时间范围、清洗版本、保留文档数和 token 数。一个来源很大，也可能主要是模板、导航和重复转载。

| 来源 | 可能带来什么 | 常见质量问题 | 需要记录什么 |
| --- | --- | --- | --- |
| 网页正文 | 广泛话题与自然表达 | 模板、广告、转载、乱码 | 抓取批次、域名、正文抽取版本 |
| 技术与学术文本 | 结构化解释与专业术语 | 公式丢失、断行、版本重复 | 来源、文档版本、解析策略 |
| 代码 | 语法与程序结构 | 生成文件、重复仓库、敏感字符串 | 仓库版本、语言、许可与过滤规则 |
| 自有领域材料 | 目标任务术语与业务知识 | 格式不统一、隐私字段、覆盖狭窄 | 授权范围、脱敏版本与时间 |

## 配比决定模型反复看见什么

假设清洗后有 80M 网页 token 和 20M 技术 token。按现有量单遍读取，技术材料占 20%。如果训练采样选择 50% 技术材料，技术池的消耗速度提高，会更早发生重复。采样权重与唯一数据量应同时报告。

设来源 $i$ 的采样概率为 $p_i$，总训练量为 $D$，那么期望来自该来源的训练 token 为 $p_iD$。若可用唯一 token 数为 $U_i$，$p_iD/U_i$ 可以粗看重复程度，但打包、过滤和采样实现会影响精确结果。

> **一句话听懂**：数据配比决定模型把有限学习机会花在哪里；比例之外，还要看每类数据有没有足够的新内容。

## 实跑对照：多读领域材料，究竟改了什么

把现有语料中的“优化器”主题作为领域池，其余九个主题作为通用池。先按原来的文档编号规则分 train / val，再分别串联；两个训练池分别有 20 / 180 份文档，含 EOS 的长度为 **5,684 / 51,256 token**。这是不同原始位置的数量，不是不同 token ID 的数量；模板本身仍大量共用。

```bash
python examples/mixture_case.py --out runs/mixture
```

脚本先保存 `design.json`，再按固定随机顺序执行六次训练。每个种子 42、43、44 都配对运行 A（领域概率 20%）与 B（50%）：模型均为默认 437,888 参数，字节编码、100 次更新、B=4、S=64、A=1、学习率计划和 **25,600 个消费 token**相同。配对内初始权重相同，只改变分池采样概率；每次运行使用新的输出目录。

每个长度 64 的窗口先抽来源，再在该池有放回抽起点，不跨池，可以跨文档 / EOS；所有目标位置参与 loss。因此概率按等长窗口定义，也对应**期望有效 token 份额**。A 期望消费领域 token 5,120，B 为 12,800，实际数必须另记，不能写成恰好 20% / 50%。

| 配对种子 | A 实际领域 token / 占比 | B 实际领域 token / 占比 | 领域 loss：A → B | 通用 loss：A → B |
| --- | --- | --- | --- | --- |
| 42 | 4,928 / 19.25% | 12,032 / 47.00% | 3.43086 → 3.35963 | 3.46337 → 3.47144 |
| 43 | 4,992 / 19.50% | 12,672 / 49.50% | 3.42456 → 3.38186 | 3.47268 → 3.49670 |
| 44 | 4,352 / 17.00% | 12,800 / 50.00% | 3.40633 → 3.32031 | 3.45245 → 3.46410 |

这是 Windows / Python 3.12.5 / PyTorch 2.11.0+cpu、FP32、1 线程的实际结果。最终独立评测对每个池固定 seed=2026、64 个长度 64 的验证窗口，即各 4,096 个目标位置；六个模型使用同一池的同一索引列表。它不同于训练中每 20 步的默认全局 16 窗口日志。验证窗口有放回且可重叠，64 个窗口不能当成 64 次独立训练重复。

三个配对的平均 B−A 为领域 **−0.06665 nats/token**、通用 **+0.01458 nats/token**：在这份模板分布和训练预算上，更多领域采样伴随领域预测改善与通用预测的小幅退步。领域池大小没有增加；例如 seed=42 的 B 消费量 / 原始池长度为 `12,032/5,684≈2.12`，表示消费强度，**不等于每个位置恰好读了 2.12 遍，也不说明覆盖了全部位置**。

原始 loss、实际计数、池文件哈希、完整验证索引与源码身份见 [mixture-reference.json](https://github.com/cjgogo27/Pretrain/blob/main/examples/results/mixture-reference.json)。成功条件是六次训练全部完成、每次两池计数之和为 25,600、固定评测身份一致且 loss 有限；**不要求 B 必须获胜**。目录冲突时换新的 `--out`，池文件缺失时先检查生成日志；不要跳过数据指纹检查。

只有三个种子，共用主题模板，没有真实领域任务，也没有统计功效或通用最优配比结论。清洗小样本在 2.2 独立运行，未混入这些训练池；本实验没有声称清洗带来了模型收益。固定 recipe 的比较动机见 [DataComp-LM Introduction 与 workflow](https://arxiv.org/html/2406.11794v1#S1)。

## 用小规模实验选择配比

先确定需要保留哪些能力，再固定分词器、模型、总训练 token 和评测设置，对照两种配比。看总体指标，也看各领域的损失与任务表现。只增加某领域数据同时增加训练总量，无法单独证明收益来自配比。

教学语料全部由项目原创，故意缩小了数据来源的不确定性。生产项目应对每类来源独立抽样审阅，核对文字能否读通、结构是否保留、时间范围是否满足需求。抽样得到的质量结论只覆盖对应分层，不能直接推及所有语料。
