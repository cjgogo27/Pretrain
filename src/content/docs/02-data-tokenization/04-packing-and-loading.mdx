## 现场问题

训练程序跑得很快，loss 也很低。检查标签才发现，每个位置的目标就是它自己；模型只需要把输入照抄出来。

> 输入、标签和注意力掩码，到底应该错开哪一位？

<SectionQA id="2.4" mode="ask" />

## 先把右移关系写出来

对 token 流 `[A, B, C, D, E]`，长度为 4 的输入是 `[A, B, C, D]`，目标是 `[B, C, D, E]`。第一个位置看到 A，预测 B；最后一个位置看到 A 到 D，预测 E。若实现已在模型内部移动标签，外部再次移动就会错两位，必须确认接口契约。

**因果掩码（Causal Mask）**阻止一个位置查看未来输入。没有它，预测 B 的位置可能直接看到 B。标签右移和因果掩码解决的是不同问题，二者都需要正确。

## Packing 不只是拼起来

**序列打包（Sequence Packing）**把短文档组合成较满的序列，减少 padding。文档之间通常插入 EOS，但 EOS 本身只是一个符号，不自动阻止注意力跨文档传播。

| 策略 | 边界如何处理 | 优势 | 需要决定什么 |
| --- | --- | --- | --- |
| 每文档单独 padding | 短文档补齐 | 结构直观 | padding 不计入损失 |
| 连续拼接 | EOS 后接下一文档 | 利用率高 | 是否允许跨文档注意力 |
| 分段 / 块对角 attention | 文档之间隔离 | 边界更明确 | 框架与内核是否支持 |

位置 ID 是否重置、EOS 是否计入损失、跨边界目标是否保留，也应写进数据规范。不存在适用于全部训练目标的唯一打包方案。

## 两篇短文档：把两种 mask 同时摊开

沿用 1.3 的真实字节 ID，第二篇文档为 `OK`：`[79,75]`。拼接后是 `Hi! EOS OK EOS`。下面是**带 padding、按文档隔离的教学变体**；它不是默认训练代码的实现。0 在这里是占位 ID，同时也是合法字节，所以必须依靠掩码说明哪些位置无效。

```text
位置         0    1   2    3    4   5    6   7
input_ids   72  105  33  256   79  75  256   0
labels     105   33 256   79   75 256    0   0
loss_mask    1    1   1    0    1   1    0   0
```

`loss_mask=0` 表示该输出不参与损失：位置 3 的 EOS 不监督去预测下一篇首字母，位置 6 后没有真实目标，位置 7 是 padding。位置 2 和 5 仍学习预测 EOS，一共 **5 个有效 token**。

attention 可见矩阵如下，行是 Query，列是允许读取的输入位置，`1=可见`：

```text
       0 1 2 3 4 5 6 7
q0     1 0 0 0 0 0 0 0
q1     1 1 0 0 0 0 0 0
q2     1 1 1 0 0 0 0 0
q3     1 1 1 1 0 0 0 0
q4     0 0 0 0 1 0 0 0
q5     0 0 0 0 1 1 0 0
q6     0 0 0 0 1 1 1 0
q7     0 0 0 0 0 0 0 1
```

padding 行保留一个自可见位置，避免整行被遮挡产生无定义 softmax；它的 loss 仍忽略。具体内核对 padding 有其他处理方式时须遵循其接口。

**attention mask 管“能读谁”，loss mask 管“评哪些输出”。**把位置 3 的 loss 设零，不会阻止位置 4 看前一篇；单独放 EOS 也不会阻止。反过来，按文档隔离 attention，不会自动忽略跨文档标签。PyTorch 不同 API 对布尔 mask 的 True 语义可能相反，矩阵转 API 时应核对：本模型 `src_mask=True` 表示禁止读取。

默认 TinyPretrain 采用连续因果窗口、无 padding、全位置计损失，允许跨 EOS 注意力，也学习窗口内的跨文档预测。上图的变体用于理解两个独立设计选择，不声称默认代码已经实现文档隔离。

## 有效 token 才是归一化分母

若有效位置集合为 $M$，token 平均损失是 $L=\sum_{i\in M}\ell_i/|M|$。有 padding 时，不能用整块张量位置数代替 $|M|$。多个微批次的有效 token 不同，直接平均它们的平均 loss 也会改变权重。

固定长度、无 padding 的教学实验中，每个微批次的有效 token 相同，按累积次数缩放损失即可。生产变长训练应对整次更新按有效 token 总数加权，并检查分布式归约的均值语义。

> **一句话听懂**：一个批次的正确性取决于 token、目标、可见范围和损失分母是否对应，而不只是张量形状能对上。

## 数据加载决定 GPU 是否在等待

大规模数据通常先离线分词，再存成可顺序读取的分片。运行时做预取、分布式切片和批次构造。要记录分片、偏移、shuffle 状态与抽样种子，才能判断恢复后是否跳过或重复样本。

TinyPretrain 为了便于学习，把每个划分串联成字节流后随机取窗口，显式构造输入与右移标签。它允许 EOS 两侧注意力相连，且用有放回随机窗口采样；“累计训练 token”因此不等于“唯一语料 token”。
