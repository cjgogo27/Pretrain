## 现场问题

训练团队交付一个 `.pt` 文件。使用方不知道词表、上下文长度、架构或数据范围，也不知道怎样验证文件是否完整。

> 怎样让别人能正确使用，并理解这份模型做过什么？

<SectionQA id="6.5" mode="ask" />

## 交付是一个成套接口

**模型交付包（Model Artifact）**通常包含权重、架构配置、分词器、使用示例、评测记录和模型卡。训练恢复快照可以另外保留，不应要求所有推理用户加载优化器状态。

| 产物 | 最小内容 | 使用方需要它做什么 |
| --- | --- | --- |
| 权重与校验 | 文件、分片索引、哈希 | 完整加载 |
| 架构配置 | 维度、层数、位置、词表等 | 重建正确网络 |
| 分词器 | 编码规则、特殊 ID、版本 | 正确输入和解码 |
| 推理示例 | 提示格式、精度、设备与采样 | 跑通第一条输入 |
| 评测报告 | 检查点身份、条件、结果与限制 | 判断是否适用 |
| 模型卡 | 目标、数据范围、风险和许可证 | 理解边界与来源 |

## 模型卡把证据写明

**模型卡（Model Card）**说明模型的预期用途、训练概况、评测条件和局限。对预训练模型要区分它是基础模型还是经过后训练的助手，避免把文本续写当作可靠事实服务。数据说明应给出可以披露的范围和处理方法，不编造无法验证的完整来源。

本项目是教学代码与教程，不随仓库提供训练好的生产模型。`examples/MODEL_CARD.md` 描述示例架构、语料与使用边界；运行后生成的权重应连同实际配置、数据指纹和评测记录再形成独立交付。

> **一句话听懂**：模型交付不仅让别人能把权重加载起来，还要让他们知道输入约定、训练身份和证据边界。

## 一次真正的复现验收

在干净环境按记录安装依赖，从固定输入运行最小命令。核对文件哈希、参数量、步数、token 计数和指标是否在预定误差内。严格逐位复现需要相同的软硬件与确定性条件；跨设备复现通常应定义数值或统计标准。

交付前还要验证从发布包重建模型，而不只是作者工作目录里的对象。路径是否可迁移、配置是否遗漏、分词器是否匹配，都是常见问题。
