## 先说实验的边界

本节训练 TinyPretrain：257 项字节词表、可学习位置嵌入、2 层因果 Transformer、隐藏维度 128、4 个头，默认上下文 64。语料由本项目原创模板和短句组成。它是机制实验，生成内容可能重复或乱码，不用于测量通用语言能力。

**从零训练（Training from Scratch）**意味着参数由随机初始化开始，没有加载已有语言模型权重。本实验不下载预训练模型，也不下载外部语料。

## 第一步：准备并检查语料

在仓库根目录运行：

```bash
python examples/prepare_data.py --out runs/data
```

脚本先按文档划分，再分别写入 `train.txt` 与 `val.txt`，并生成 `manifest.json`。你可以打开文本检查内容，也可以对照清单中的哈希。两侧共享教学主题，文档身份不同不表示语义完全独立。

## 第二步：运行训练

```bash
python examples/train.py --data runs/data --out runs/tiny --steps 100
```

每步的输入取长度 $S+1$ 的窗口：前 $S$ 个 token 为输入，后 $S$ 个为目标。模型使用因果掩码，交叉熵对每个有效位置求平均。完成累积、梯度检查和裁剪后，AdamW 更新参数。

| 输出 | 读它可以知道什么 |
| --- | --- |
| `metrics.jsonl` | 每次评估对应的 step、loss、PPL、token 与学习率 |
| `latest.pt` | 最新可恢复训练状态 |
| `sample.txt` | 用当前模型采样的演示片段 |
| 终端日志 | 训练进度与全局端到端吞吐 |

CPU 运行速度依机器而异。可以用 `--threads 1` 减少小模型线程开销，或减小层数和宽度做结构检查。不要把“短跑结束”当作达到语言质量门槛。

> **一句话听懂**：这个实验让每一块都有实物：文本文件、ID、logits、loss、梯度、权重与可恢复状态。

## 本轮实际跑出了什么

2026-10-15 在 Windows、Python 3.12.5、PyTorch 2.11.0+cpu、FP32、1 线程、seed=42 下，用上述默认配置执行 100 步。模型 **437,888 个独立参数**；B=4、S=64、A=1、DP=1，故每更新 256 token，总计 **25,600**。验证使用固定的全局 16 个窗口，共 1,024 个目标位置。

| 更新步 | 累计训练 token | 最近更新 train loss | 固定窗口 val loss | PPL |
| --- | --- | --- | --- | --- |
| 20 | 5,120 | 4.748636 | 4.682485 | 108.0382 |
| 40 | 10,240 | 4.109130 | 4.074328 | 58.8109 |
| 60 | 15,360 | 3.588485 | 3.687630 | 39.9501 |
| 80 | 20,480 | 3.602930 | 3.512109 | 33.5189 |
| 100 | 25,600 | 3.687634 | 3.442558 | 31.2668 |

![CPU 教学实验的训练与固定窗口验证损失曲线](/Pretrain/figures/cpu-loss.svg)

训练点只表示最近一次更新的 loss，不是整个训练集均值；验证窗口可重叠，只有一个种子，没有误差条。训练与验证 loss 的不同方向或大小不能脱离这些口径解释。

生成时以“预训练”为提示、温度 1、独立采样种子 200042，采样 80 个字节 token。下面是 `sample.txt` 的 **JSON 转义形式**，控制字符保留为 `\uXXXX` 或 `\n`，不是人工修饰后的通顺例句：

损失下降而采样仍有大量乱码，是这个极小字节模型的实际结果。它没有把任意字节序列限制成合法 UTF-8，`errors='replace'` 会显示替换字符；小语料、短训练也没有提供通用表达能力。不能把这条曲线当成流畅语言生成的证据。

## 怎样判断成功，失败后先查什么

| 检查 | 成功条件 | 常见失败与第一步 |
| --- | --- | --- |
| 语料生成 | 200 train / 40 val 文档，两个文本与 manifest 存在 | 路径错误：从仓库根目录执行并打开文件 |
| 训练 | 有限 loss；最后 step=100、tokens=25,600；产生三个运行文件 | CUDA 不可用：保持默认 CPU；词表 / 长度错误：打印 ID 与形状 |
| 重复运行 | 每个新实验使用新的输出目录 | `fresh output directory`：另选目录，不向旧日志混写 |
| 恢复 | 同代码同计划同数据下，连续 / 恢复最终状态一致 | identity / plan / fingerprint mismatch：先查差异，不能删检查绕过 |
| 解释 | 报告限定为机制与这份数据 | 生成不流畅不是这项机制测试的失败，也不证明泛化良好 |

## 第三步：演练暂停与恢复

```bash
python examples/train.py --data runs/data --out runs/paused --steps 100 --stop-after 40
python examples/train.py --data runs/data --out runs/resumed --steps 100 --resume runs/paused/latest.pt
```

两条命令总计划都是 100 步，第一条只在第 40 步提前退出。第二条保留原计划继续，不把学习率终点改成新的值。输出目录可以不同，核心训练配置必须一致。

```bash
python examples/verify_resume.py
```

本轮实际执行 `verify_resume.py`：12 步连续运行，与第 6 步中断后恢复的模型、AdamW、RNG、采样器和计数一致，累计 768 token。脚本还实际检查了数据变化、学习率代码乘以 1.01、缺失代码身份、计划、world size 和 PyTorch 版本不匹配时的拒绝行为，以及仅加载权重新建运行时的状态重置。结束后清理自身临时目录；详细结果与环境见参考 JSON。

## 怎样解释结果

想继续追踪“换数据 / 换切分 / 换等待时间”各改变什么，可按下面顺序运行。每个 `--out` 使用新目录；成功条件、失败排查和结论边界在对应章节，无新增下载依赖。

| 命令 | 预期产物与先看什么 | 正文解释 |
| --- | --- | --- |
| `python examples/cleaning_case.py --out runs/cleaning` | raw.jsonl、report；核对误删与漏删 | [2.2](/Pretrain/02-data-tokenization/02-cleaning-deduplication/) |
| `python examples/mixture_case.py --out runs/mixture` | design / report、六次训练；核对消费量与验证身份 | [2.1](/Pretrain/02-data-tokenization/01-sources-and-mixture/) |
| `python examples/parallel_case.py --out runs/parallel` | report；四类张量误差与调度依赖 | [4.5](/Pretrain/04-training-distributed/05-tensor-pipeline-context-parallel/) |
| `python examples/profile_case.py --out runs/profile` | report、两份 trace；区分剖析与基准计时 | [5.4](/Pretrain/05-evaluation-diagnosis/04-throughput-and-profiling/) |
| `python examples/verify_ddp_training.py --out runs/ddp-training` | PASS、report 和日志；两层验证均通过 | [6.3](/Pretrain/06-tools-practice/03-single-to-multi-gpu/) |

先看 loss 是否有限、步数与 token 是否符合配置，再检查恢复验证。如果 loss 有变化而文本仍不好，这并不矛盾：小语料、短上下文和极小模型本来不足以获得广泛语言能力。真正的质量结论需要更合适的数据、预算和独立评测。
