## 现场问题

同事说：“这个模型只有几十万参数，你可以在 CPU 上训练。”打开文件，你却看见词表、嵌入、注意力、前馈层和一个叫 LM Head 的输出层。

> 哪些东西负责表示文本，哪些东西真正决定下一步预测？

## 先看输入和输出

输入是整数张量 `input_ids`，形状为 $[B,S]$。$B$ 是每个批次的序列数，$S$ 是每条序列的 token 数。模型输出 **logits**，形状为 $[B,S,V]$，$V$ 是词表大小。Logits 是未归一化得分；对词表维做 softmax，才得到下一个 token 的概率分布。

**参数（Parameters）**是训练过程中通过梯度更新的数值。Token ID、原始文本、优化器状态和训练日志都不属于模型参数，但都影响能否正确训练或使用模型。

## 从 ID 到概率，经过哪些部件

| 部件 | 接收什么 | 做什么 | TinyPretrain 的选择 |
| --- | --- | --- | --- |
| Token embedding | token ID | 查表得到向量 | 257 个 ID，包括 EOS |
| 位置表示 | 序列位置 | 让网络区分顺序 | 可学习位置嵌入 |
| 因果注意力 | 各位置的向量 | 汇集当前位置可见的历史 | 4 个注意力头 |
| 前馈网络 | 每个位置的表示 | 做非线性变换 | 隐藏维度的 4 倍 |
| 残差与归一化 | 子层输入和输出 | 连接信息流、调整数值尺度 | Pre-LayerNorm |
| LM Head | 最后的隐藏表示 | 映射为词表得分 | 与 token embedding 共享权重 |

教学默认配置为 2 层、隐藏维度 128、上下文 64。它使用字节作为基本单位：UTF-8 中一个汉字可能占多个字节，因此 64 token 不等于 64 个汉字。特殊 ID 256 表示文档结束 EOS；普通字节占 0–255。

## 看一次具体交接

假设一个批次有 4 条序列，每条长 64，嵌入后是 $[4,64,128]$，输出得分是 $[4,64,257]$。计算损失时，将它与同样包含 256 个目标位置的标签比较。标签不是从得分中生成的，而是原始 token 流右移一位得到的。

网络内部有很多向量，它们没有“第 7 维专门存事实”这样的预设解释。我们可以研究表示的统计性质，但不能把一个维度简单当作一条人类可读规则。

> **一句话听懂**：模型把 token ID 变成上下文相关的向量，再把向量变成下一 token 的得分；各模块的接口就是这些张量。

## 小模型与生产模型差在哪里

教学模型保留了自回归训练的主链，但没有采用 RoPE、RMSNorm、SwiGLU、GQA 或 MoE。生产架构的这些变化分别影响位置表示、数值稳定、容量、缓存和通信，不能只改模型名称就宣称复现。

检查一个模型时，先核对词表、隐藏维度、层数、注意力头数、位置方案与上下文长度。参数量只是其中一项，同样参数量的模型可能有不同的显存、吞吐和数据需求。
