## 现场问题

训练 loss 一直下降，验证 loss 却不再改善。你换了一套分词器，困惑度又突然变小，似乎“进步”了很多。

> 哪些变化代表泛化改善，哪些只是评估口径变了？

<SectionQA id="5.1" mode="ask" />

## 在未参与更新的数据上测量

**验证损失（Validation Loss）**在固定、未用于当前训练更新的数据上计算。评估时关闭训练特有行为，使用 `eval()` 和无梯度模式，并保持目标右移、掩码与归一化规则正确。无梯度模式不自动切换 dropout，二者都要设置。

训练损失与验证损失之间的差异可以提示过拟合、数据分布差异或测量方式不同，但单看差值不能唯一确定原因。例如训练时有 dropout、验证时没有，或者训练 loss 来自在线随机批次，都会影响两条曲线的可比性。

## 困惑度如何从损失得到

若采用自然对数、对有效 token 平均的交叉熵 $L$，**困惑度（Perplexity）**为 $\operatorname{PPL}=\exp(L)$。例如 $L=2$ 对应 PPL 约 7.39。它衡量模型对数据的平均不确定程度，不是回答正确率，也不是候选词表中固定剩下几项。

| 比较条件 | 能否直接比较 token PPL | 原因 |
| --- | --- | --- |
| 同分词器、同验证集、同口径 | 可以作为一项指标 | 预测单位一致 |
| 更换分词器 | 通常不能 | token 的单位与数量改变 |
| 更换语言或领域 | 需分开解释 | 预测难度与分布改变 |
| 不同截断 / 窗口策略 | 需统一策略 | 可见上下文不同 |

跨分词器可考虑按字节等共同单位归一化的指标，但仍需统一文本、处理方式和边界约定。不能仅因为 PPL 更低就断言换分词器后的模型更强。

> **一句话听懂**：验证损失是在固定未见数据上的预测误差；困惑度只是它的一种变换，比较前必须先统一单位。

## 多卡和长文档如何汇总

分别累计每个 rank 的负对数似然总和与有效 token 数，然后全局求和相除。若不同 rank 或批次 token 数不同，不能简单平均局部平均值。长文本滑动窗口评估还要说明重叠部分是否重复计入。

教学脚本使用固定种子的验证窗口，按每个批次相同长度采样并汇总。它测量的是固定抽样窗口上的估计值，窗口可重叠，不是对全部验证 token 的不重复穷举；日志明确记录采样批次数。

## 低损失之后还要看什么

分来源、语言与长度报告损失，有助于发现总体均值掩盖的退化。再结合能力评测判断是否达到目标。TinyPretrain 的语料规模很小，验证损失只用于观察训练和恢复链路，不应把它解释为真实世界任务能力。
